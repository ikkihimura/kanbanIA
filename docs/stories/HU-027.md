# HU-027 — Soporte de Windows

Hito: M4

Dependencias: 022

Responsable recomendado: agent-integration-engineer + desktop-ui-engineer

## Historia

Como usuario de Windows quiero instalar y usar Kanban IA, incluidos los agentes, con las mismas garantías que en macOS.

Contexto (decisión del propietario, 2026-11-26): Windows queda **fuera del alcance por ahora** y es **experimental, sin soporte**. La CI (`ci.yml`) compila y pasa todas las pruebas automáticas en `windows-2025`, y el workflow de instaladores genera el `.msi` y el `-setup.exe` (NSIS), publicados en la pre-release `v0.2.0`, pero nadie los ha instalado. Sin máquina Windows. Opciones valoradas: Docker no sirve (macOS no ejecuta contenedores Windows y estos no tienen escritorio); sí una máquina virtual Windows 11 ARM (UTM o VMware Fusion, x64 emulado) o una prueba de instalación silenciosa en la CI.

## Criterios de aceptación

- [ ] CA-1: Smoke manual con el `.msi` y con el `-setup.exe`: instalación limpia, abrir, crear datos, actualizar desde una versión anterior conservando los datos y desinstalar (con y sin la casilla «borrar datos» de NSIS). Si se usa una máquina virtual ARM, registrarlo como limitación.
- [ ] CA-2: Agentes en Windows: Claude Code y Codex arrancan con sus adaptadores; aislamiento de los datos de la app (HU-023: hoy Claude Code va sin sandbox en Windows y el perfil de Codex no se ha comprobado) decidido por el propietario e implementado o documentado como limitación aceptada.
- [ ] CA-3: Procesos y permisos: comprobar el Job Object al cancelar y al cerrar la app de golpe (HU-018/024), y los permisos de `service.json` con `KANBANIA_DATA_DIR` (hoy hereda la ACL del directorio).
- [ ] CA-4: Guías (`docs/INSTALAR.md`, `docs/AGENTES.md`, README) sin la marca «experimental» solo para lo comprobado.

## Verificación requerida

Smoke manual en Windows (no basta la CI); pruebas reales de agentes solo con autorización del propietario (suscripción, sin claves); revisión security del aislamiento. No publicar ni crear releases sin instrucción.

## Límites y entrega

Aplicar CLAUDE.md y docs/ARQUITECTURA.md. Implementar únicamente este alcance. Documentar cualquier decisión necesaria. Entregar evidencia por CA, pruebas ejecutadas y limitaciones; actualizar BACKLOG solo con resultados comprobados.
