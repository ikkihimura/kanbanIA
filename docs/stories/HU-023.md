# HU-023 — Aislar los datos de la app de los agentes

Hito: M4

Dependencias: 021

Responsable recomendado: agent-integration-engineer + security-reviewer

## Historia

Como usuario quiero que un agente que ejecuto no pueda leer los datos privados de Kanban IA, para que un repositorio o un prompt malicioso no le haga filtrar tokens ni mi planificación.

Contexto (HU-021, comprobado con Codex real el 2026-11-16): Codex lee archivos sin pedir permiso, también fuera del worktree, y los worktrees viven dentro de `<data_dir>`. Puede leer la base (`kanbania.sqlite3`), `service.json` (token de sesión del servicio local) y `codex-home/auth.json`. Claude Code pide permiso para leer fuera del `cwd` con su herramienta Read, pero `cat` de una ruta externa no se ha probado.

## Criterios de aceptación

- [ ] CA-1: Elegir con el propietario el mecanismo (por ejemplo: sandbox del sistema para el proceso del adaptador —`sandbox-exec` en macOS, AppContainer/token restringido en Windows—, mover worktrees y secretos fuera del alcance, o solo aviso explícito) y documentar la decisión y su alcance real por plataforma.
- [ ] CA-2: Con el mecanismo activo, un agente real no puede leer la base, `service.json` ni las copias de `backups/`; Codex sigue pudiendo usar su `codex-home` y el worktree, y Claude Code su sesión. Lo que no se pueda impedir en una plataforma se muestra al configurar el agente y en la guía (docs/AGENTES.md), sin afirmar protección inexistente.
- [ ] CA-3: Probar `cat`/lectura directa de rutas externas con ambos agentes y registrar el resultado; el modelo de amenaza de mismo usuario (CLAUDE.md, «Ejecución supervisada») se actualiza.

## Verificación requerida

Pruebas reales autorizadas (sin coste extra) con Claude Code y Codex intentando leer `<data_dir>/kanbania.sqlite3` y `service.json`; prueba automatizada del mecanismo con el agente falso; revisión security. Windows: registrar la limitación si no se puede verificar.

## Límites y entrega

Aplicar CLAUDE.md y docs/ARQUITECTURA.md. Implementar únicamente este alcance, con UI cuando se menciona. No agregar capacidades de hitos posteriores. Documentar cualquier decisión necesaria. Entregar evidencia por CA, pruebas ejecutadas y limitaciones; actualizar BACKLOG solo con resultados comprobados.
