# HU-025 — Retención de datos de ejecuciones

Hito: M4

Dependencias: 018,011

Responsable recomendado: rust-engineer + desktop-ui-engineer

## Historia

Como usuario quiero que los intentos antiguos no llenen el disco ni el repositorio, y decidir qué se conserva.

Contexto: sin retención de `runs/<id>/` (salida JSONL, hasta 4 MiB por intento), worktrees de intentos terminados, ramas `kanbania/*` ni `mutation_receipts`. Restaurar una copia anterior deja worktrees sin fila. Las ramas pueden contener trabajo que la persona quiere conservar.

## Criterios de aceptación

- [ ] CA-1: Política decidida por el propietario (por ejemplo, días o número de intentos) y configurable en «Sistema»; nunca borra un intento activo, una entrega pendiente de revisión ni una rama sin confirmación explícita.
- [ ] CA-2: Limpieza visible: la UI muestra cuánto ocupa y qué se borraría antes de hacerlo; los worktrees huérfanos (sin fila tras restaurar) se detectan y se ofrecen para eliminar con las mismas comprobaciones de HU-018 (cambios, ignorados, HEAD).
- [ ] CA-3: `mutation_receipts` tiene retención sin romper la idempotencia dentro de su ventana; documentado en README y CLAUDE.md.

## Verificación requerida

Pruebas con reloj controlable y SQLite temporal real; worktrees reales en un repositorio temporal; copia restaurada con worktrees huérfanos; `npm run check`; revisión quality.

## Límites y entrega

Aplicar CLAUDE.md y docs/ARQUITECTURA.md. Implementar únicamente este alcance, con UI cuando se menciona. No agregar capacidades de hitos posteriores. Documentar cualquier decisión necesaria. Entregar evidencia por CA, pruebas ejecutadas y limitaciones; actualizar BACKLOG solo con resultados comprobados.
